# 用一块 ESP32-S3 主控板替代原来的两块 Mega2560

> 本文说明**为什么要替代、替代后是什么、新板子和原两块板如何对应**。
> 画 PCB 的逐区块规格见同目录 `BOARD_SPEC.md`；固件说明见 `README.md`；
> 共用的上位机映射算法见 `../motion_pipeline.py`。

---

## 1. 现在的系统：两块 Mega2560 是怎么分工的

### 1.1 硬件与职责

工程原本用 **2 块 Arduino Mega2560 扩展板**（`控制器（嘉立创打板）/全伺服通用版--网口`），
两块板刷**同一份固件** `servoController.ino`，靠"收到的帧里放了哪几个轴"区分职责：

| 板子 | FlyPT 发送字符串 | 实际驱动 |
|---|---|---|
| 1 号板 | `<255><255><Axis1a><Axis2a><Axis3a><Axis4a>` | 电缸 1~4 |
| 2 号板 | `<255><255><Axis5a><Axis6a><Axis4a><Axis3a>` | 电缸 5~6（帧里 4/3 位是冗余值，通常未接） |

两块板各插一根 USB 到 PC 的两个 COM 口，**板间没有任何连线、互不通讯**——
它们是地位对等的"哑从机"，真正的协调者是 PC（FlyPT Mover / 上位机）。

### 1.2 每块板内部做什么

`servoController.ino` 的核心逻辑只有三步：

1. **收串口帧**：等连续两个 `255`，再收 4×16-bit 大端值。
2. **映射行程**：`mappedPos = pos / 1.7`，把 FlyPT 的 0~65535 映射到 0~`maxPos=38400`
   步（总行程 192mm）。
3. **发步进脉冲**：用 **4 个 16 位硬件定时器**（Timer1/3/4/5）产生脉冲，
   周期 `samplePeriod(4000) / |目标-当前|`，钳位在 `[minPeriod=39, 4000]µs`——
   离目标越远越快、越近越慢（自带减速曲线）。ISR 每脉冲 `currentPos += incPos`，到位停定时器。

### 1.3 与伺服驱动的接口

从工程 `网口线序图.pdf` 确认，实物伺服（东能/日鼎/东菱）是
**24V 供电 + 差分脉冲输入**，通过 RJ45 连接：

```
RJ45: 1=24V+  2=24V-  3=使能  4=脉冲+  5=方向+  6/7=脉冲-/方向-  8=空
```

原板用 RJ45 座 + 差分驱动把定时器信号转成差分送给伺服。

## 2. 为什么要替代（两块板的痛点）

| 痛点 | 说明 |
|---|---|
| **两块板、两根 USB** | 接线多、COM 口占用多、任一板掉线系统就不完整 |
| **定时器资源限制** | Mega2560 只有 4 个 16 位定时器，所以每块最多驱 4 轴——这是"必须用两块板"的根本原因，不是算力不够 |
| **无位置反馈** | 纯开环，丢步无从知晓 |
| **无限位保护** | 原固件没有限位开关输入，机械超程无保护 |
| **无看门狗** | 上位机断流后平台停在最后姿态，不会自动回中 |
| **抗干扰靠电容** | 原板在 RESET-GND 间接 10µF 电容抗干扰，属于被动补救 |
| **5V 逻辑、老平台** | ATmega2560 已老旧，生态和维护成本上升 |

---

## 3. 替代方案总览

### 3.1 用一块 ESP32-S3 单芯片代替两块 Mega

**核心理由不是"双核"，而是 ESP32-S3 有 8 路 RMT（远程控制收发器）外设**——
每路 RMT 都能独立、硬件地产生脉冲序列，一块芯片就能驱动 6 路步进，
不再需要"4 定时器 = 4 轴"的限制。双核（另一个 CPU 核）只是额外好处：
可以把通信/监控放在另一核，脉冲产生完全由 RMT 硬件承担，**不受 WiFi/软件干扰**。

> 一句话：**一块顶两块，靠的是 8 路 RMT，不是靠双核。**

### 3.2 新旧对照表

| 项目 | 原双 Mega2560 | ESP32-S3 单板 |
|---|---|---|
| 控制板数量 | **2 块** | **1 块** |
| 脉冲产生 | 定时器中断（软件+定时器） | **RMT 硬件**（更稳，无抖动） |
| 每板轴数 | 4 轴（定时器限制） | 6 轴（8 路 RMT） |
| 串口帧 | 2 帧各 4 轴，两根 USB | **1 帧 6 轴，一根 USB** |
| 步进速率 | `4000/|diff|` µs，钳位 39µs | 相同规律（固件保留） |
| 行程映射 | `pos/1.7` → 0~38400 步 | 完全相同（兼容） |
| 电平 | 5V | 3.3V（板子加 74HCT245 转 5V） |
| 限位 | 无 | **6 路（新增）** |
| 急停 | 无 | **硬件级切断使能（新增）** |
| 看门狗 | 无 | **500ms 无帧自动回中位（新增）** |
| 远端升级 | 无 | 预留 WiFi（将来可甩掉 USB） |

### 3.3 职责对应关系

```
原系统:
  PC帧1(Axis1~4) ──USB──> Mega#1 ──4路定时器──> 差分/RJ45 ──> 伺服1~4
  PC帧2(Axis5,6,4,3) ─USB─> Mega#2 ──4路定时器──> 差分/RJ45 ──> 伺服5,6

新系统:
  PC单帧(Axis1~6) ──USB──> ESP32-S3 ──6路RMT──> 74HCT245(3.3→5V)
                                      ──AM26LS31(单端→差分)──> 6×RJ45 ──> 伺服1~6
```

## 4. 新主控板要有哪些功能（概述）

板子按 8 个功能区块设计，详细器件/连接见 `BOARD_SPEC.md`：

| 区块 | 作用 |
|---|---|
| **A 电源** | 5V 输入 → 3.3V LDO；24V 不进板子，只透传到 RJ45 |
| **B ESP32 最小系统** | WROOM-1 模块、EN/BOOT、USB、天线净空 |
| **C 电平转换** | 74HCT245 ×2，3.3V→5V（**用 HCT 不用 HC**） |
| **D 差分驱动** | AM26LS31 ×2，单端→差分；6 个 RJ45 按工程线序 |
| **E 限位/急停** | 6 路上拉限位输入 + 硬件级急停切断使能 |
| **F 通信** | USB 主通道，预留 UART/RS485/WiFi |
| **G 指示/调试** | LED、复位/下载键、SWD、测试点 |
| **H 抗干扰** | EN 电容、π 滤波、TVS、单点共地、差分等长 |

## 5. 它在整个数据链里的位置（重要：主控不改算法）

```
游戏PC(GTA5) → UDP遥测 → 仿真/上位机PC
                            ├─ motion_pipeline.py  ← 加速度→姿态映射(已修好,左右对称)
                            ├─ 洗出/低通/限速      ← 算法层(已修好,保护主控)
                            ├─ IK → 6轴位移(mm)
                            └─ serial_bridge.py ──USB串口帧──> 【ESP32-S3 主控】 ──> 电缸
                                                               ↑ 只做执行，不做算法
```

**关键分工**：
- 所有"加速度→姿态→缸位移"的**算法都在电脑端**（`motion_pipeline.py`）完成。
- 主控板**只是执行层**：收 6 轴位移 → 转步数 → RMT 发脉冲。
- 因此换板子**不需要改任何映射算法**，两块 Mega 时代调好的体感参数原样保留。

## 6. 协议：兼容但有一步改动

| | 原双板 | 新单板 |
|---|---|---|
| 帧头 | `<255><255>` | **不变** |
| 数据 | 4×16bit / 帧 | **6×16bit / 帧** |
| 映射 | `16bit/1.7 → 0~38400` 步 | **不变** |
| 中位 | 32768 → 19200 步 | **不变** |

电脑端用 `serial_bridge.py --single-board` 发单帧 6 轴：
```bash
cd sim/G_chair_hw
../G_chair_mujoco/.venv/bin/python -u serial_bridge.py \
    --single-board --port1 /dev/ttyUSB0 --verbose
```
固件 `G_chair_esp32/src/main.cpp` 解析这个 14 字节帧（2 头 + 12 数据）。

## 7. 新增的安全特性（原板没有）

1. **上电使能互锁**：ENA 默认禁止，收到第一帧合法数据才使能。
2. **限位保护**：任一限位触发 → 立即停该轴脉冲。
3. **急停**：硬件级，按钮直接切断 24V→使能回路，**不依赖固件**。
4. **看门狗**：超过 500ms 无有效帧 → 6 轴回中位（平台自动放平）。

> 注意：限位/急停是**纯机械保护的第一道防线**，固件逻辑是第二道。
> 两类都要有，不能只靠软件。

## 8. 迁移实施步骤

1. **画板 / 打样**：按 `BOARD_SPEC.md`，重点确认 RJ45 线序和差分驱动。
2. **空载测试**（拆掉电缸）：USB 接电脑，用逻辑分析仪看 6 路差分输出波形/频率是否随目标变化。
3. **确认极性**：DIR 方向、ENA 有效电平（默认低有效，改 `ENABLE_ACTIVE_LOW`）。
4. **确认线序**：RJ45 的 1/2=24V±、3=使能、4/6=脉冲±、5/7=方向±。
5. **逐轴上电**：手托电缸，验证方向、限位触发、急停。
6. **接入上位机**：`serial_bridge.py --single-board` 发帧，观察 6 轴是否按预期动作。
7. **对比验收**：同样一段遥测，分别驱动新板和原板，缸位移应一致（映射算法相同）。

## 9. 风险与待办

| 项 | 说明 |
|---|---|
| **未带真实电机验证** | 固件已编译通过，但没接真实伺服跑过——必须空载→逐轴验证 |
| **24V 与板子隔离** | 24V 只走 RJ45，不进低压部分；共地于一点，避免环流 |
| **差分线布线** | Pulse±/Dir± 等长相邻，远离电源和数字信号 |
| **GPIO 改动** | 若画板时改了引脚，必须同步改 `config.h` 的数组 |
| **闭环（可选）** | 当前开环；要闭环需加编码器/磁栅尺接口（第二版） |
