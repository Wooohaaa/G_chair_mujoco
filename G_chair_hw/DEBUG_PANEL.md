# 主控调试面板（连接真实 ESP32-S3）

一个浏览器界面的调试测试工具，用来替代 FlyPT Mover 的"调试/测试"功能，
直接连接我们的 ESP32-S3 主控板。

## 能做什么

| 功能 | 说明 |
|---|---|
| **串口连接** | 自动检测 USB 串口，或手动指定；也支持无硬件的模拟模式 |
| **手动姿态测试** | 9 个预设动作（中位/升沉±/横滚±/俯仰±/偏航±），点一下平台就执行 |
| **自定义位姿** | 6 个输入框直接输入电缸位移 mm（±95），精确控制每根缸 |
| **实时状态** | 20Hz 显示 6 缸目标/实际步数、缸速(mm/s)、限位、使能、看门狗 |
| **实时曲线** | 6 缸位移曲线（实线=实际、虚线=目标），红字告警缸速超限 |
| **软件急停** | 一键回中位（硬件急停仍是物理按钮，直接切 24V） |
| **数据录制** | 保存每帧 6 缸实际/目标、限位、使能、看门狗到 CSV |

## 运行

```bash
cd sim/G_chair_hw
./../G_chair_mujoco/.venv/bin/python debug_panel.py --port 8765
# 浏览器打开 http://localhost:8765
```

| 参数 | 说明 |
|---|---|
| `--port 8765` | HTTP 端口（WebSocket 自动用 +1 = 8766） |
| `--serial /dev/ttyUSB0` | 指定串口（不指定则自动检测第一个） |
| `--baud 115200` | 波特率 |
| `--simulate` | 模拟模式，无硬件时先验证界面 |

> 当前这台电脑没接 ESP32（之前接的是 RK3566），可以先用 `--simulate` 看界面。

## 与主控的协议

面板通过 USB 串口和 ESP32 通讯，两个方向：

**下行（面板 → 主控）**：二进制指令帧（与 `servoController.ino` / `serial_bridge.py` 一致）
```
<255><255> + 6×uint16 大端
16bit / 1.706640625 (65535/38400) -> 步数 (0~38400)，中位 32768 -> 19200（0mm 严格对齐，已修原 1.7 的 +0.37mm 误差）
```

**上行（主控 → 面板）**：文本状态帧（固件 `src/main.cpp` 每 50ms 发一次）
```
$cur0,cur1,...,cur5,tgt0,...,tgt5,limitMask,enabled,watchdog\n
以 $ 开头，与二进制指令帧区分；limitMask 6 位，bit i=1 表示轴 i 限位触发
```

## 验证记录（2026-11）

用虚拟串口对（socat）模拟 ESP32，完整链路验证通过：

| 测试 | 结果 |
|---|---|
| 预设"左倾" | 缸3(roll) 目标 +5mm ✓ |
| 自定义 `[10,20,30,-5,-5,6]` | 6 缸精确到位 ✓ |
| 软件急停 | 全部回 0 ✓ |
| 真实串口帧 | 面板发 `[32767,32767,43115,...]`，模拟主控正确解析为 +30mm ✓ |
| 状态回传 | 模拟主控回帧后面板显示 `cur_mm` 正确 ✓ |

## 固件要求

主控固件需使能状态回传（已加到 `G_chair_esp32/src/main.cpp`，编译通过）：
每 50ms 发一帧 `$` 开头的文本状态。若你用的旧固件没有此功能，
面板仍可发指令，但状态区会显示全 0。

## 与 FlyPT Mover 调试功能的对照

| FlyPT 调试功能 | 本面板 |
|---|---|
| 实时数据流监控 | ✅ 20Hz 状态 + 曲线 |
| 手动测试各轴 | ✅ 预设动作 + 自定义位移 |
| 滤波器调参 | ✅ **已实现**（在主 `host_app.py` Web 界面，滑块实时改增益/低通/洗出/限速，自动保存） |
| 数据录制 | ✅ CSV |
| 多游戏数据源 | ❌ 不需要（我们只用 GTA5 mod） |

> 本面板专注**手动姿态测试**；在线调参请直接用 `./run.sh host-sim/host-real`
> 的主 Web 界面（localhost:8765），参数改动实时生效且重启后保留。
